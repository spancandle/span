# span keeper and tape

Requires Node 26.11.1. Install with `npm ci`, then run `npm run typecheck` and `npm test`. The package imports the sibling `program/client`.

Run `npm run keeper` to record reads, extend eligible ticket tails and settle every expired ticket. Run `npm run tape` separately to serve seven JSON snapshots on `127.0.0.1:8789`. The tape does not use a signing key and an HTTP request never calls RPC. With `KEEPER_RELEASE_HOURS=1` the keeper also opens the candle of every release hour in `src/common/release-hours.json` a day ahead and reads it without a ticket. With `SPAN_EVENT_HOURS` set to a file of listed hours (`npm run hours -- add …` writes it), it opens and reads those hours the same way, and the tape publishes them with their reasons in `hours.json`. The tape also publishes the reason a seller wrote as a memo in the transaction that opened a candle. With `KEEPER_ASSETS=SOL,BTC,ETH` it also opens the BTC and ETH candles of each release hour, one and two seconds after the SOL candle. The tape records each asset's DOVES account separately and marks every candle, ticket and receipt with its asset. The keeper also closes the `Until` account of a ticket that has been settled or withdrawn and returns its rent to the seller. `tickets.json` shows a ticket's selling end inside the hour, and tickets and receipts bought inside the hour carry the price paid. It also closes a `Resale` offer once its ticket is settled and returns the rent to the holder. `tickets.json` shows a ticket's open offer and the transfers it has had, and receipts carry the transfers. It also closes a `Bid` once its time has passed or its ticket is settled, when the bidder's token accounts exist, and returns its USDC, SPAN and rent to the bidder. `tickets.json` lists a ticket's open bids, and each transfer says whether it came from a resale or a bid. With `KEEPER_HALF_HOURS=1` it also opens and reads the 30-minute candle of each release and listed hour for every asset in `KEEPER_ASSETS`, three to five seconds after the minute. The tape's paths serve 60-minute candles only, as before; the same files under `/v2/` serve both lengths and give each candle its `secs`.

Both processes load the repository root `.env` when present. `SPAN_CLUSTER` defaults to `devnet`. Public cluster RPC is always first. Optional devnet endpoints use `DEVNET_RPC_URL_FALLBACK`, `DEVNET_RPC_URL_FALLBACK_2`, `DEVNET_RPC_URL_FALLBACK_3` and their `DEVNET_RPC_WS_URL_FALLBACK`, `DEVNET_RPC_WS_URL_FALLBACK_2`, `DEVNET_RPC_WS_URL_FALLBACK_3` equivalents. Mainnet read endpoints use the names without `DEVNET_`. `SPAN_WS_URL` overrides only the public WebSocket. Endpoint URLs are never logged.

`KEEPER_KEYPAIR` defaults to `keys/<cluster>-keeper.json` relative to the repository root. Keep key files private and outside version control. Use a dedicated fee wallet. **Do not run two keeper processes with the same key.** Different fee wallets can operate independently. Sending to mainnet is disabled unless `KEEPER_ALLOW_MAINNET=1`; deployment and mainnet operation require separate operator setup.

Priority fees use the positive 75th percentile, clamped by `KEEPER_PRIORITY_FEE_MIN` and `KEEPER_PRIORITY_FEE_MAX` (default 10,000 and 1,000,000 microlamports/CU). `KEEPER_CREATE_BUDGET_LAMPORTS` defaults to 50,000,000 per trailing 24 hours. When the recipient needs an account and the budget is exhausted or its finalized history is incomplete, settlement waits. Settlements requiring no account creation continue. Release-hour and listed-hour candles count against the same budget.

`KEEPER_DATA_DIR` defaults to `keeper/data`. Give each fee wallet its own data directory, including when running different keys concurrently. A single blockhash expiration height is stored durably there before signing. After a restart, reads and marks start immediately. Account-creating settlements wait for finalized history beyond the previous height; if the height file is missing they wait ten minutes before reconstruction. Pending creation costs remain reserved until a complete finalized recount proves their result or expiration.

Anyone can settle one ticket with their own fee wallet, including while the public keeper's creation budget is exhausted:

```sh
SPAN_CLUSTER=devnet KEEPER_KEYPAIR=keys/my-wallet.json NO_DNA=1 npm run settle -- <ticket-address>
```

This command simulates, creates any necessary receiving accounts, and sends an atomic settlement transaction. Buyer and seller signatures are unnecessary. Replaced receiving accounts belong to the original recipient; memo-required Token-2022 ATAs receive their remainder in a fresh normal token account.

Tape storage uses built-in SQLite under `TAPE_DATA_DIR` (default `keeper/data`) and atomically publishes `public/state.json`, `tickets.json`, `feed.json`, `history.json`, `chain.json`, `status.json`. `TAPE_HOST` and `TAPE_PORT` default to 127.0.0.1 and 8789. Stop with SIGTERM. Restart backfills confirmed program transactions and retains receipts after ticket closure. Feed gaps represent recorder outages or unreadable transaction history, not a pause in oracle publications. Budget wait counts reach status.json through a local Unix socket; the socket is ephemeral and persists no decision state. The generated timestamp freezes when state is stale; chain snapshots stop updating when the blockhash is older than 15 seconds. Consumers must check freshness.

Run optional historical replay with `SPAN_REPLAY_DIR=<input-directory> NO_DNA=1 npm test`. `npm run devnet:e2e` runs real-time integration scenarios and uses devnet SOL and test tokens. `npm run observe:mainnet` is a read-only one-hour oracle recording check. Generated data and keys are ignored by git.
